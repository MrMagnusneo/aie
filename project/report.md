Проект строит модель, которая оценивает шахматный ход только среди легальных ходов позиции. Вход модели: позиция `board` и кандидатный `legal_move`. Выход: вероятность того, что этот ход относится к хорошим ходам.

## 2. Постановка задачи

Предметная область - шахматы и ранжирование ходов. Пользователь сервиса передает FEN-позицию, а сервис возвращает лучший ход и несколько кандидатов.

ML-формулировка:

- вход: FEN позиции и ход в UCI;
- признаки: one-hot кодирование фигур на 64 клетках, сторона хода, рокировки, поля from/to, промоция, тип фигуры, взятие, шах и геометрия хода;
- целевая переменная: `label = 1`, если ход входит в верхнюю часть ходов по reward-функции;
- задача: бинарная классификация и дальнейшее ранжирование легальных ходов по вероятности класса `1`.

Ключевые метрики:

- `ROC-AUC` и `Average Precision` - качество отделения хороших ходов от остальных;
- `F1` - баланс precision/recall для положительного класса;
- `Top-1 good rate` - доля позиций, где лучший выбранный ход попал в группу хороших.

## 3. Данные

Внешний датасет не используется. Данные генерируются внутри проекта через `python-chess`.

Пайплайн генерации:

1. Создается стандартная начальная доска.
2. Генерируются короткие self-play партии.
3. Для каждой позиции перечисляются все легальные ходы.
4. Каждый ход получает reward по эвристикам: мат, шах, взятие, промоция, материал, рокировка, центр, развитие и активность.
5. Верхние `20%` ходов по reward получают `label = 1`, остальные - `label = 0`.

Файл `data/generated_self_play.jsonl` содержит `20669` примеров. Каждая строка включает `position_id`, `fen`, `move_uci`, `label`, `reward`, `san`.

## 4. Модели и подходы

Baseline - тактическая эвристика без обучения. Она учитывает немедленные признаки: взятие, шах, промоцию, рокировку, центр и развитие.

Финальная модель - `RandomForestClassifier`. Она обучается на self-play примерах и использует более богатое представление позиции и кандидатного хода. Такой подход является RL-like: агент сам генерирует опыт и получает reward, но финальное обучение выполнено как supervised classification по сгенерированным переходам.

Почему выбран такой вариант:

- не нужен внешний датасет;
- всегда ранжируются только легальные ходы;
- легко объяснить на защите;
- воспроизводится на обычном компьютере;
- ближе к архитектуре chess engine, чем прямое предсказание хода из фиксированного словаря.

## 5. Экспериментальный протокол и результаты

Конфигурация эксперимента:

- `num_games = 32`;
- `max_plies = 24`;
- `positive_fraction = 0.2`;
- `n_estimators = 60`;
- `max_depth = 9`;
- разбиение train/validation выполняется по `position_id`, чтобы ходы одной позиции не попадали одновременно в train и validation.

Результаты из `artifacts/metrics.json`:

| Модель | Accuracy | F1 | ROC-AUC | Average Precision | Top-1 good rate |
|---|---:|---:|---:|---:|---:|
| Tactical baseline | - | - | - | - | 0.838 |
| RandomForest ranker | 0.864 | 0.718 | 0.923 | 0.811 | 0.869 |

Финальная модель выбрана потому, что она улучшила `Top-1 good rate` относительно baseline и показала высокий `ROC-AUC`. Это означает, что модель хорошо ранжирует хорошие и плохие ходы внутри множества легальных ходов.

## 6. Архитектура решения и сервис

Пайплайн:

```text
python-chess board
  -> legal moves
  -> feature encoder
  -> RandomForest probability
  -> sorted legal candidates
  -> best move
```

API:

- `GET /health` - состояние сервиса и информация о модели;
- `POST /predict` - принимает `fen` и `top_k`, возвращает лучший ход и список кандидатов.

Пример запроса:

```bash
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"fen":"rnbqkbnr/pppppppp/8/8/8/8/PPPPPPPP/RNBQKBNR w KQkq - 0 1","top_k":5}'
```

Если FEN некорректный, сервис возвращает HTTP 400. Если позиция терминальная и легальных ходов нет, возвращается статус `no_legal_moves`.

## 7. Наблюдаемость, конфигурация и безопасность

Логи:

- сервис логирует загрузку модели;
- если артефакт отсутствует, сервис обучает маленькую bootstrap-модель и пишет предупреждение.

Конфигурация:

- параметры обучения вынесены в `configs/train.yaml`;
- путь модели задается через `MODEL_PATH`;
- пример переменных окружения лежит в `.env.example`.

Безопасность:

- секреты и токены не используются;
- внешние пользовательские данные не сохраняются;
- `.env` не нужен для запуска и не должен попадать в репозиторий.

## 8. Docker

Проект обязательно поддерживает Docker.

```bash
docker build -t chess-move-classifier .
docker run --rm -p 8000:8000 chess-move-classifier
```

Во время сборки Docker обучает небольшую демонстрационную модель, поэтому контейнер сразу готов отвечать на `/predict`.

## 9. Ограничения и дальнейшая работа

Ограничения:

- reward-функция эвристическая, без Stockfish;
- модель не считает долгосрочные варианты на много ходов вперед;
- self-play короткий, поэтому шахматная сила ограничена;
- RandomForest выбран как стабильный учебный baseline, а не как максимальная по силе шахматная модель.

Развитие:

- добавить MCTS;
- обучать value-функцию по результатам партий;
- сравнить с более сильными моделями;
- добавить ELO-турнир против baseline;
- опционально использовать Stockfish как teacher для отдельного эксперимента.

## 10. Сценарий демонстрации
